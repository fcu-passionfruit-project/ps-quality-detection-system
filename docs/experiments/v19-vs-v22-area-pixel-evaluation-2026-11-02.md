# v19 vs v22：面積比例誤差與像素分割品質

- 日期：2026-11-02（整理自〈Segment 模型評估方式白話解析〉）
- 評估設計：柏宇
- Baseline：`training/runs/segment/v19_defect_epoch200_pw050_cp01`
- 部署模型：`training/runs/segment/v22_D_context6`（與 Django 的 `Defect.pt` 相同）
- 評估方法：見 README〈局部瑕疵模型評估方式〉

## 設定

- 評估單位：一張照片 × 一類瑕疵；同類 mask 取聯集。
- 分母：果實內切橢圓遮罩內的 pixel 數。
- confidence：`0.25`，與 Django 部署相同。
- 資料：驗證集 93 張、測試集 92 張；以下為測試集。
- 面積指標沿用系統的 mask 縮放方式；像素指標先移除 letterbox 補邊。

## 結果（test，92 張）

| 瑕疵 | 有瑕疵的照片 | `MAE_GT+`（pp） | Pixel Recall | Pixel F1 | 解讀 |
| --- | ---: | --- | --- | --- | --- |
| anthracnose 炭疽病 | 5 | 0.46 → 0.23 | 62.6% → 78.9% | 0.69 → 0.77 | 變好，但只有 5 張樣本 |
| insect_track 畫圖蟲 | 30 | 12.58 → 10.71 | 32.0% → 43.3% | 0.45 → 0.56 | 變好，但仍大幅低估面積 |
| abrasion 擦傷 | 39 | 0.82 → 0.95 | 36.5% → 20.0% | 0.45 → 0.30 | 變差，21／39 張完全沒抹到 |
| insect_bite 蟲咬 | 3 | 0.25 → 0.25 | 0 → 0 | 0 → 0 | 兩版都抓不到 |

補充數字：

- v22 畫圖蟲 `bias` −3.06 pp，模型常常塗不滿。
- 由 v22 畫圖蟲的 `bias` 與像素 P／R 推算，標註的畫圖蟲平均約佔果皮兩成，模型在有畫圖蟲的照片上平均少算約 9.8 pp（推算值，原報告未列平均標註面積）。
- 擦傷 `MAE_GT−` 0.084 → 0.055：v22 在 `0.25` 門檻下對擦傷較保守，誤報少但漏檢多。
- v22 蟲咬 `MAE_GT−` 0.0053 > 0，代表在沒有蟲咬的照片產生誤報。
- v19 蟲咬完全沒有預測，Pixel Precision 是 0／0，無定義，應記為「—」而非 0。

`MAE_all` 與 Pixel F1 已依公式逐一驗算，與報告一致。

## 結論

1. v22 改善炭疽病與畫圖蟲，但擦傷明顯退步，不是全面勝出。
2. 舊的 mAP 分析曾記錄擦傷 mAP50 0.278 → 0.330，和本次面積／像素結論相反。mAP 看跨門檻的整體排序；本評估看固定門檻 `0.25` 下的實際覆蓋，兩者衡量的問題不同。
3. 蟲咬測試集只有 3 張、訓練集約 26 個實例，無法可靠評估，列為研究限制。
4. 選模依驗證集 Mask mAP 與三 seed 穩定度，未用測試集挑選。

## 已知問題

- repo 中的 `passionfruit/evaluation/evaluate_experiment_d_area.py` 只比較 D0／D1／D2，沒有 v19，也沒有移除補邊的像素指標。本頁數字來自柏宇本機的更新版本，需 push 回 repo 才能重現。
- 部署端 `fruit_app/detection.py`（硬體 repository）直接把 `masks.data` 以 `cv2.resize` 拉到 ROI 大小，未開 `retina_masks`。`masks.data` 含 letterbox 補邊，瑕疵遮罩可能有輕微位移與面積縮放。XGBoost 以同一套特徵訓練，對判級影響應有限；此為讀程式推論，尚未實測。
- 四個 YOLO 模型都以照片隨機切分，未依 `fruit_id`，分數可能偏樂觀。
